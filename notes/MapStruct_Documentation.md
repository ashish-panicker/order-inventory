# MapStruct Mappers & Annotations: A Comprehensive Guide

When building enterprise Java applications using a layered architecture, it is a strict best practice to decouple your internal database representations (Entities) from the data exposed to the outside world (DTOs/Records). 

This is where **MapStruct** comes in. MapStruct is a Java annotation processor for the generation of type-safe bean mapping classes. Instead of writing tedious boilerplate code to manually map fields from an `Order` entity to an `OrderResponse` DTO, MapStruct generates that code for you at compile time.

---

## 1. Why Do We Use DTOs and Mappers?

Before understanding the annotations, it is crucial to understand *why* we don't just return database entities directly from our API endpoints.

* **Security & Encapsulation:** Entities often contain sensitive fields (e.g., passwords, soft-delete flags, internal database IDs) that should not be exposed to the client.
* **API Stability:** Database schemas change frequently. By using DTOs, you can change your internal database tables without breaking the public API contracts your mobile apps or frontend rely on.
* **Data Aggregation:** A DTO might combine data from multiple entities, or omit fields to keep the JSON payload lightweight.

Mappers (like MapStruct) act as the bridge, transferring data between the internal Entity world and the external DTO world.

---

## 2. The `@Mapper` Annotation

### What it does
The `@Mapper` annotation is placed on a Java interface to mark it as a mapping interface. When you build the project (via Maven or Gradle), MapStruct detects this annotation and automatically generates an implementation class for the interface.

### Example Usage
```java
import org.mapstruct.Mapper;

@Mapper(componentModel = "spring")
public interface OrderMapper {
    OrderResponse toResponse(Order order);
}
```

### Key Attributes
* `componentModel = "spring"`: This is the most important attribute for Spring Boot applications. It tells MapStruct to annotate the generated implementation class with `@Component`. This allows you to inject the mapper into your services using standard Spring dependency injection (`@Autowired` or constructor injection via Lombok's `@RequiredArgsConstructor`), rather than relying on `Mappers.getMapper()`.

---

## 3. The `@Mapping` Annotation

### What it does
By default, MapStruct automatically maps fields that have the **exact same name and compatible types** in both the source and target objects. For example, if both `Order` and `OrderResponse` have a field named `status` of type `String`, MapStruct maps them automatically.

However, when field names differ, or when you need to transform the data (like formatting a date), you use the `@Mapping` annotation to instruct MapStruct on exactly how to handle that specific field.

### Example Usage
```java
import org.mapstruct.Mapper;
import org.mapstruct.Mapping;

@Mapper(componentModel = "spring")
public interface OrderMapper {

    @Mapping(target = "createdAt", source = "createdAt", dateFormat = "yyyy-MM-dd'T'HH:mm:ss'Z'")
    @Mapping(target = "orderId", source = "internalOrderId") // Example of differing field names
    @Mapping(target = "sensitiveData", ignore = true)        // Example of ignoring a field
    OrderResponse toResponse(Order order);
}
```

### Key Attributes
* `source`: The name of the field in the input parameter (the Entity).
* `target`: The name of the field in the return type (the DTO).
* `dateFormat`: Extremely useful for parsing or formatting `java.time.LocalDateTime` or `java.util.Date` objects into specific String formats for API responses.
* `ignore = true`: Explicitly tells MapStruct not to map a specific target field, which is useful when the DTO has a field that will be populated manually later.
* `expression = "java(...)"`: Allows you to write raw Java code to determine the value of a field if the transformation is highly complex.

---

## 4. How It Works Behind the Scenes

Unlike reflection-based mapping libraries (like ModelMapper or Dozer) which map data dynamically at runtime and can be slow, **MapStruct works at compile time**.

When you ran `./mvnw compile`, MapStruct hooked into the Java compiler and generated a class usually named `OrderMapperImpl.class` inside the `/target/generated-sources/annotations/` directory.

The generated code looks exactly like what a human would write:

```java
// Generated by MapStruct
@Component
public class OrderMapperImpl implements OrderMapper {
    @Override
    public OrderResponse toResponse(Order order) {
        if (order == null) {
            return null;
        }

        // Standard mapping
        String orderId = order.getOrderId();
        String status = order.getStatus();
        BigDecimal totalAmount = order.getTotalAmount();
        
        // Custom formatting instructed by @Mapping(dateFormat = "...")
        String createdAt = null;
        if (order.getCreatedAt() != null) {
            createdAt = DateTimeFormatter.ofPattern("yyyy-MM-dd'T'HH:mm:ss'Z'")
                                         .format(order.getCreatedAt());
        }

        return new OrderResponse(orderId, status, totalAmount, createdAt);
    }
}
```

Because it uses standard getter/setter calls (or constructor initialization for Java Records), MapStruct is incredibly fast, type-safe, and errors are caught immediately during the build process rather than failing unexpectedly in production.
